# ADR-6: HITL interrupts fire at superstep boundaries

**Decision:** Interrupts are evaluated by `InterruptController.maybeInterrupt` **before** a node executes, at a superstep boundary, never from inside a node body. A raised interrupt throws `GraphInterrupted`, the interpreter returns `{ status: "interrupted", checkpointRef, pending }`, and a later process resumes from that checkpoint. `InterruptInsideFanOut` rejects, at validation time, any HITL node reachable only through a fan-out edge.

**Context:** Critical operations (git commits, deploys, planner clarification) must pause for human approval, and the approval round trip spans separate CLI invocations. The source documents place `interrupt()` inside node bodies while simultaneously fanning those nodes out in parallel.

**Options Considered:**

| Option | Pros | Cons |
|--------|------|------|
| **A. In-node interrupt with restart-from-top resume** (the documents' prescription, and LangGraph's actual semantics) | A node can pause at any point after arbitrary computation; the framework idiom is well documented; multiple pause points per node are possible | Documented behaviour is that "the node restarts from the beginning of the node where the `interrupt` was called when resumed, so any code before the `interrupt` runs again" (https://docs.langchain.com/oss/javascript/langgraph/interrupts) — so every file write, git operation or history append preceding the pause executes twice on every resume. Combined with fan-out, resume re-enters sibling branches that already committed. Multi-interrupt nodes match resume values strictly by index, making call order load-bearing |
| **B. In-node interrupt plus an idempotency discipline on node bodies** | Keeps the framework idiom; the double-execution hazard is neutralised where the discipline is followed | The discipline is unenforceable — nothing in a type or a schema prevents a future contributor adding a write before a pause; the failure is a duplicated commit or a duplicated history entry discovered in production |
| **C. Boundary interrupt evaluated before node execution (selected)** | No node body ever re-runs, so the double-execution class does not exist; the checkpoint at the pause is a single consistent snapshot with no branch mid-flight; per-branch approvals batch naturally at the fan-in barrier so one interrupt covers N branches | A node cannot pause partway through its own work — a pause point must be modelled as its own node, so an approval that depends on an intermediate computation requires splitting that computation out |

**Rationale:** The **success criterion that each state key is written exactly once per superstep** (asserted by a write-counter spy across 8 concurrent branches) eliminates Options A and B: under restart-from-top, a resumed superstep re-enters branches whose writes already committed, producing duplicate writes that no reducer can distinguish from legitimate ones. Option B is additionally eliminated because the required discipline has no enforcement point, whereas Option C converts the hazard into two compile-time validator errors (`InterruptInsideFanOut`, `EffectfulNodeContainsHitl`) that a later edit cannot reintroduce. Boundary interrupts are only available because ADR-1 owns the runtime; they are not expressible on a framework whose resume unit is the node.

**Consequences:** `InterruptController` delegates to the shipped subsystem rather than inventing a second approval path — `getCheckpointMechanismFor` (`checkpoints/registry.ts:105`) resolves the mechanism and `runWithAudit` records the outcome to `.bober/audits/<runId>.jsonl`, so `bober approve` / `bober reject` and the nine documented checkpoint ids keep working. `hitl_commit` sits at the fan-in barrier, batching approval for every branch in one interrupt. Nodes carrying `effects: ["git"]` are reachable only from a HITL gate, enforced by `EffectfulNodeContainsHitl` plus an inbound-edge rule; in non-interactive mode with no approval record they block fail-closed with an audit entry.

**Risk:** Modelling every pause point as its own node inflates node count and forces intermediate values that were node-local into `OverallState` or into `refs`. If a required approval genuinely depends on a large intermediate result, that result must be offloaded to `ScratchStore` and referenced — never inlined — or the 4 KiB `maxInlineBytes` guard rejects the commit.
