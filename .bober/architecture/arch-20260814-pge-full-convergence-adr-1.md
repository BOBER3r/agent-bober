# ADR-1: Fan-out checkpoints stay illegal — the runtime cannot hold a per-branch interrupt

**Decision:** `InterruptInsideFanOut` remains a blocking validation error. A human-in-the-loop interrupt is sound only on a node reachable WITHOUT traversing a fan-out edge — the join/barrier pattern ADR-6's Option C already supports and already permits — never on a node that re-executes once per concurrently-dispatched branch. `validate.ts`'s diagnostic message is amended to name the reason; the diagnostic code, its severity, and the set of legal topologies are otherwise unchanged.

**Context:** `spec-20260814-pge-full-convergence`'s `audits` divergence needs five of the imperative pipeline's checkpoint ids declared inside the sprint fan-out region, which `InterruptInsideFanOut` (`validate.ts:1089-1099`) blocks. `arch-20260805-pge-graph-engineering-adr-6`'s own stated hazard is double execution under restart-from-top resume — an argument about WHERE an interrupt fires, not whether a fan-out branch may host one; its Rationale calls the fan-out clause the belt-and-braces consequence of that decision, and its Consequences call it merely unnecessary ("per-branch approvals batch naturally at the fan-in barrier"), never unsound. That narrower claim licenses this revisit.

**Options Considered:**

| Option | Pros | Cons |
|---|---|---|
| (a) One approval for all N branches, asked at the join outside the region | Already legal and already expressible — the join fires once, `branchKey: null`, at the first node outside the region (`interpreter.ts:1571-1579`) | A pause cannot depend on a computation still mid-flight inside one branch |
| (b) One approval per branch, HITL declared inside the region | Reads as "approve branch X specifically" | Three independent runtime facts make it unsound today (Rationale) |
| (c) A barrier gate inside the region, asking once for all branches | Reads as "the" natural fan-in point | `reduce_sprints`, the artifact's only in-region barrier gate, has no `fanout`-kind inbound edge and so is bound by the same per-branch reachability as any other in-region node (`validate.ts:602-607`) — it is (b) wearing (c)'s name |

**Rationale:** Option (b) is eliminated by three runtime facts distinct from ADR-6's restart-from-top hazard: (1) `Checkpoint.interrupt` is one `InterruptRecord | null` (`checkpointer.ts:247`) — nowhere to hold N concurrent pauses. (2) `grantScope` carries no branch key (`interrupt.ts:268`) and `clearScope` deletes every key sharing its prefix before a fresh pass asks (`interrupt.ts:371-375`, `:485`) — a sibling branch's arrival evicts an already-granted branch's approval; `interrupt.test.ts:794` pins that eviction as intended for the single-scope case, and per-branch fan-out is the same eviction one level down. (3) `resumeMessageId` is `hitl:<checkpointId>` with no branch key (`interrupt.ts:332`) and its consumer matches by node id alone (`nodes/plan.ts:142-144`) — N branch decisions collapse onto one message row. Option (c) fails for the same reason as (b): `reduce_sprints`'s only inbound edge, `e-sprint-released`, is `kind: "normal"`, not `"fanout"` (`coding.graph.ts:1174`), so the validator's own reachability computation places it inside the region, not exempt from it. Option (a) needs no new machinery — the join already fires once outside the region — which is exactly what `hitl_commit` uses today, just further downstream. The failure mode of (b) is also CAP-DEPENDENT: serialized at cap 1 a grant may be consumed before a sibling clears it, concurrent at cap 8 it is not (`frontier.ts:13,29-32`) — behaviour that varies with concurrency is precisely what this graph's byte-identical-at-cap-1-and-8 determinism criterion forbids.

**Consequences:** `audits` cannot converge: 5 of the 6 undeclared checkpoint ids (pre-curator, pre-generator, pre-evaluator, pre-code-reviewer, post-sprint) sit inside the fan-out region and stay undeclarable; `spec-20260814-pge-full-convergence`'s feat-3 AC2 is amended to record this rather than pass quietly. **Correction to ADR-6:** its Consequences state `hitl_commit` "sits at the fan-in barrier" — false for the shipped artifact. `hitl_commit`'s only inbound edge is `e-doc-approval` from `documenter`, outside the region via the evaluation path, not via `reduce_sprints`; `reduce_sprints`, the artifact's actual named barrier, is itself inside the region (see Options) and could not host a HITL node under ADR-6's own rule either.

**Risk:** If a future runtime change gives `Checkpoint.interrupt` a keyed, branch-aware slot and `grantScope`/`resumeMessageId` a branch discriminator — sprint 2's territory, explicitly out of this ADR's scope — option (b) becomes sound and this decision must be revisited; the three facts in Rationale are falsifiable conditions, not a permanent verdict.
