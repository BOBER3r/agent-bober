# ADR-2: Topology artifact format, authoring form, and how G1 is achieved

**Decision:** The topology is authored as a plain typed object literal (`export const CODING_GRAPH: TopologySpec` in `src/pge/topology/coding.graph.ts`), serialized by `bober pge dump` into a committed `.bober/topology/<graphId>.json` carrying `graphId`, `graphVersion`, `provenance` and a `sha256` checksum, and **loaded from that JSON file by the runtime** — never from the TypeScript module.

**Context:** G1 requires validate/visualize/diff without executing a node; G4 requires the graph be a versionable, CI-gateable, optimisable artifact. A serialization derived from a compiled runtime graph cannot satisfy either, because it describes what the compiler produced rather than what was authored.

**Options Considered:**

| Option | Pros | Cons |
|--------|------|------|
| **A. Derive the artifact from runtime introspection** (`getGraphAsync().toJSON()` / `drawMermaid()`) | Free — no format to design or maintain; always matches the compiled graph | Describes a *compiled* graph; expands conditional edges into edges to every declared target and never serialises the router body; carries no port types, prompt refs, model tiers, cache policies or loop bounds; its shape changes when the library changes, so it cannot be a versioned contract |
| **B. Hand-edited JSON as the authoring source** | The artifact is unambiguously the source of record; no build step | No type inference, no IDE navigation, no refactoring support; node/reducer/schema references are unchecked until runtime; a typo in a `nodeId` is discovered by a failed run |
| **C. Fluent builder DSL** (`defineGraph().llm().gate().edge().build()`) | Type inference during authoring; method names guide correct construction | ~300 lines of mini-language to maintain for zero capability gain over a typed literal; conflicts with the "Small utility modules" principle in `.bober/principles.md` |
| **D. Plain typed object literal → committed JSON (selected)** | Full `tsc` inference and refactoring on the authoring source; the artifact is plain data with no executor in its module graph; `dump --check` makes drift a CI failure; the runtime loads the JSON, so the JSON is load-bearing | Two representations must be kept in sync, enforced only by the `dump --check` gate |

**Rationale:** The **success criterion "`bober pge validate` exits non-zero with a distinct named code for each of 30 malformed fixtures, with zero node executions enforced by a module-graph boundary, not by assertion"** eliminates Option A: an introspection-derived artifact requires the runtime to be constructed, so the executor is always reachable. It also eliminates A on the **"non-empty topology diff without a `graphVersion` bump fails CI"** criterion, since a library-owned serialization has no stable version this repo controls. Option B is eliminated by the **Locked Dependency "TypeScript strict + ESM/NodeNext"** with zero type errors as a hard gate — a hand-edited JSON graph puts every node, reducer and schema reference outside the typechecker. Option C is eliminated because it delivers no capability Option D lacks while adding a maintained DSL, and the panel identified it as speculative abstraction.

**Consequences:** `src/pge/topology/**` is governed by an ESLint `no-restricted-imports` boundary forbidding `src/pge/runtime/**`, `src/pge/nodes/**`, `src/orchestrator/**` and `src/providers/**` — the same scoped idiom already enforcing local-only telemetry (`eslint.config.js:46-48`) and zero-egress medical (`:75-77`). `EffectRegistry.seal()` is called by `dump`, so even a widened boundary cannot perform an effect during topology production. `validateTopology` ships two modes: `structural` (artifact only, valid on a base-branch file whose refs may not exist on head) and `full` (resolves `schemaRef`/`promptRef`). Optimiser output carries `provenance: "optimizer"` and is excluded from `dump --check`, which applies only to `provenance: "authored"`; promotion is an explicit human step rewriting the literal.

**Risk:** If `dump --check` is ever made non-blocking, the committed JSON silently diverges from the literal and the runtime executes a topology nobody reviewed. The gate must run in the same blocking CI job as `validate`, `docs --check`, `diff --require-version-bump` and `audit-state`, with no `continue-on-error`.
