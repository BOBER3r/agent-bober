# ADR-3: Router outcome labels are serialized in the artifact

**Decision:** Every `router` node declares a closed set of outcome labels in the topology (`targets: Array<{ label, to }>`); the router body selects a label and is structurally unable to name a node id, and a returned label outside the declared set is a typed `UndeclaredRouteLabel` failure. `diffTopology` reports `routeLabelsAdded` and `routeLabelsRemoved`.

**Context:** G1 requires structural diffing and G4 requires the diff be a CI merge gate. Routing logic is where a graph's behaviour actually changes, so a diff blind to routing is a diff of the least interesting part of the topology. This mechanism was identified by two independent panel lenses as the highest-value idea available and is grafted in from a runner-up design.

**Options Considered:**

| Option | Pros | Cons |
|--------|------|------|
| **A. Router body returns a node id** (LangGraph conditional-edge style) | Maximum expressiveness — a router can compute any destination at runtime; no schema surface to maintain | The set of reachable destinations is not knowable from the artifact, so `UnreachableNode` and `NoTerminalPath` degrade to guesses; a change in routing logic produces an empty structural diff, which is precisely the G1 capability the design exists to deliver |
| **B. Free-text `condition: string` on conditional edges** | Records *that* a branch exists and gives a human-readable hint; cheap to add | The condition is an opaque string the validator cannot check and the differ cannot interpret; adding a new outcome inside the router body still produces no diff, so it inherits Option A's blindness while looking like it solved it |
| **C. Closed outcome-label set declared per router (selected)** | Every reachable destination is enumerable from the artifact, so reachability and terminal-path analysis are exact; adding a possible route is a visible structural change that trips the version-bump gate; an undeclared label fails loudly at runtime instead of silently routing | Routers cannot compute a destination the author did not anticipate; every new outcome requires a topology edit and a `graphVersion` bump |

**Rationale:** The **success criterion "a non-empty topology diff without a `graphVersion` bump fails CI"** eliminates Options A and B: under either, a change that alters which node executes next produces an *empty* diff, so the gate passes while behaviour changed — the gate becomes decorative. The LangGraph research confirms this is not a hypothetical: its serialization iterates `branch.ends` and emits an edge to every declared target while "the router *function* is not serialised, so a structural diff of routing logic still needs your own spec layer above LangGraph". Option C is the spec layer that research names, and it is only available because ADR-2 places artifact ownership in this repo.

**Consequences:** `NodeSchema`'s `router` variant carries `targets: z.array(RouteTargetSchema).min(1)`. Two validator codes exist for it: `RouterTargetNotDeclared` (a `targets[].to` naming an unknown node or an out-of-scope node) and `UndeclaredRouteLabel` (an edge carrying a `label` no router declares). `Goto` gains `kind: "label"` so a node returns `{ kind: "label", label: "retry" }` rather than a node id; the interpreter resolves the label through the compiled adjacency. Cycle detection (`UnboundedCycle`, via Tarjan SCC) becomes exact rather than conservative, because every back-edge is declared.

**Risk:** A genuinely data-dependent destination — for example fanning out to one branch per sprint contract — cannot be expressed as a fixed label. This is handled by a separate edge kind (`fanout`) whose target is a single subgraph and whose *cardinality* is runtime-determined, so the topology hash stays invariant to contract count (R32). If a future requirement needs a destination that is neither a declared label nor a fan-out into a fixed target, this decision blocks it and the schema must be extended deliberately rather than by widening `Goto` to accept arbitrary node ids.
